# 0.10 Documents — livraison 3 (signature en ligne) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Faire signer en ligne, par un lien personnel et un code reçu par e-mail, la convention ou le contrat d'un dossier et le devis envoyé ; le PDF signé porte une page de preuve ; le devis signé passe à « Accepté ».

**Architecture:** Service commun du socle `Core\Signatures` (table `signature_requests`, page publique `signature/{token}`, code e-mail, page de preuve fusionnée au PDF par Gotenberg, évènement `SignatureCompleted` après commit). Le socle ne connaît ni les documents ni le devis : le sujet est un alias polymorphe ; Documents et Crm écoutent l'évènement pour leurs sujets.

**Spec:** `docs/superpowers/specs/2026-11-19-0.10-documents-signature-design.md` (§ Signature en ligne, § Devis « Bon pour accord »).

## Global Constraints

Celles des livraisons 1 et 2, plus :
- Lien : jeton aléatoire de 40 caractères, seul `token_hash` (sha256) stocké, valable **30 jours** (fin de journée de Paris) ; même page « Lien invalide ou expiré » pour tout lien inconnu, expiré, annulé ou déjà signé.
- Code : 6 chiffres, haché, valable **10 minutes**, **5 essais** ; un nouveau code remplace le précédent ; au plus un envoi par minute.
- Le PDF d'origine n'est jamais écrasé ; le PDF signé = original + page de preuve (signataire, e-mail, date et heure de Paris, adresse IP, navigateur, empreinte SHA-256 du document d'origine, numéro de la demande).
- Signature électronique **simple** ; aucune donnée de signature dans les logs ; IP, navigateur, nom et e-mail du signataire dans `$auditPersonal`.
- Routes publiques sous `throttle:signature-public` (limiteur nommé).
- Le devis signé passe à « Accepté » (date de Paris), comme le bouton actuel ; aucun dossier créé.

## Review Focus

- Code faux 5 fois : la demande se bloque (nouveau code nécessaire), jamais de signature.
- Document annulé ou devis refusé entre l'envoi du lien et la signature : lien invalide.
- Deux onglets qui signent en même temps : une seule signature (verrou).
- Gotenberg en panne à la signature : rien n'est signé, message français, on peut réessayer.
- Devis qui n'attend plus de réponse au moment de la signature : la signature est refusée (« Ce devis n'est plus en attente de réponse »).

### Task 1: Fusion de PDF et service `Core\Signatures`

`Core/Documents/PdfRenderer::merge(list<string> $pdfs): string` (Gotenberg `/forms/pdfengines/merge`) ; migration `signature_requests` (RLS) ; `Core/Signatures/SignatureRequest` (modèle, `MORPH_ALIAS`), `Signatures::request(string $subjectType, string $subjectId, string $pdfPath, string $pdfSha256, string $signerName, string $signerEmail, ?string $signerPersonId, User $by): array{request: SignatureRequest, token: string}` (annule la demande précédente du même sujet), `Signatures::cancelFor(string $subjectType, string $subjectId)`, `Signatures::find(string $token): ?SignatureRequest` (valide seulement), `sendCode`, `sign(SignatureRequest, string $code, string $ip, string $agent): SignatureRequest` ; évènement `Core/Signatures/Events/SignatureCompleted` (`subjectType`, `subjectId`, `requestId`, `signedAt`) ; modèles d'e-mails `signature_request` (`{lien}` obligatoire), `signature_code`, `signature_done` ; tests `tests/Feature/Core/SignaturesTest.php`.

### Task 2: Page publique de signature

Routes `signature/{token}` (page), `signature/{token}/pdf`, `signature/{token}/code`, `signature/{token}/sign`, `signature/{token}/signed` (PDF signé, après signature, pendant 30 jours) ; page `resources/js/pages/public/signature.tsx` (lecture, case « J'ai lu et j'accepte », Recevoir mon code, code, Signer) ; limiteur `signature-public` ; tests HTTP.

### Task 3: Documents : demander la signature

`DocumentSignatures::request(User, Document, string $email)` (convention et contrat seulement, document non annulé) ; statut `signature_pending`, puis `signed` à l'évènement, dossier « Convention signée » (`Paperwork::markConventionSigned`) ; bloc du dossier : « Demander la signature », état, PDF signé ; annuler un document annule sa demande ; anonymisation : nom, e-mail, IP, navigateur effacés.

### Task 4: Devis « Bon pour accord »

`Crm\Quotes\QuoteSignatures::request(User, Quote, string $email)` (devis en attente de réponse) ; à l'évènement : `QuoteTransitions::accept` (date de Paris) et PDF signé enregistré comme exemplaire signé (`QuoteSignedCopy::storeContent`) ; refus/expiration/nouvelle version annulent la demande ; bouton sur la page du devis ; anonymisation.

### Task 5: Docs, e2e, suite complète

`documents.md` § 7, `crm.md` (devis), `admin.md`, `data-dictionary.md`, CHANGELOG, CLAUDE.md ; e2e : demander la signature d'une convention, ouvrir le lien, recevoir le code (lu dans la base de test par une route de test ? non : e-mail capturé par Mailpit de la pile e2e si présent, sinon test HTTP seulement) ; suite complète.
