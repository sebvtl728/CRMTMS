# 0.8.1 Écrans de formation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Session page in steps with a Synthèse of progress cards, sessions kanban, séances pushed to the trainer's Outlook, training dashboard with « Créer une session », tasks and notes on a session.

**Architecture:** One server service (`SessionChecklist`) computes the progress cards for one or many sessions in grouped queries; the session page keeps all its data and switches steps client-side (URL `?etape=`); the kanban reuses `SessionListQuery`; Outlook gets a generic source registry beside the untouched CRM-action path; Catalogue gets a `TrainingBlocks` registry Sessions fills.

**Tech Stack:** Laravel 12 / PHP 8.4, Inertia + React 19 / TS, shadcn, `@dnd-kit/core`, PostgreSQL 17 (FORCE RLS), Pest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-17-0.8.1-ecrans-formation-design.md` (§ 4 decisions, § 6 clarifications — binding).

## Global Constraints

- French UI and messages; Paris days (`TrainingSession::today()`, `WorkingDays::day`); integer minutes/cents.
- Every new business table: `tenant_id uuid not null`, `BelongsToTenant`, `Rls::enable`, UUID v7, soft delete; migrations via `--database=pgsql_owner`.
- Boundaries: Sessions reaches CRM only through `Crm\Public\*`, Catalogue only through `Trainings`/`TrainingData`/`TrainingUsage`; Catalogue, Connectors, Crm, Core never import Sessions (`ModuleBoundariesArchTest`).
- No role-name test in business code: rights and scopes only (`SessionsVisibility::allows($user, $permission, $session)`).
- Personal text (`session_notes.body`, `session_tasks.title`) in `$auditPersonal`; never in Outlook, logs or `connector_runs`.
- A user-facing error = `UserFacingHttpException` (French) or a validation error.
- Steps: `synthese|configuration|planning|stagiaires|suivi`, default `synthese`; legacy `?tab=` converted (`Session`→`configuration`, `Planning`→`planning`, `Présences`→`suivi`).
- Kanban: columns Planifiée, Confirmée, En cours, Terminée (+ Annulée behind « Afficher les annulées »); Terminée = ended < 90 days; ≤ 50 cards per column then « Voir les N autres »; drag only Planifiée ↔ Confirmée when `effective()` is one of them.
- Outlook copy: trainer of a planned séance of a non-cancelled session, trainer linked (`trainers.user_id`) to a user with an active `CalendarLink`; title « <libellé de la session> — <module> »; no trainee, note, adaptation need nor price. CRM action push unchanged.
- Tasks: title ≤ 200, due day optional, assignee optional (active user of the tenant), done by/at. Notes: body ≤ 5 000, edit by author only, delete by author or who may update the session.

## Review Focus

1. A session with hundreds of séances or a kanban page of 200 sessions: the Synthèse / pastille stay a fixed number of queries (Task 1 query-count test).
2. A trainer changed on a séance (single, bulk, generator): the old trainer's Outlook copy is deleted, the new one created (Task 5 test).
3. A card whose data the user cannot see (no `sessions.dossiers.view`, no attendance right) is absent, not shown as ✓ (Task 1 test).
4. Old bookmarks `/sessions/{id}?tab=Planning` still land on Planning (Task 2 test).
5. Dragging a session the user may not update, or one now « En cours »: refused, card back in place, French message (Task 4 test).
