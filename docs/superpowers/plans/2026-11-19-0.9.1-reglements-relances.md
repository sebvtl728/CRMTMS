# 0.9.1 Règlements et relances Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record payments against validated invoices, show what is paid / left / overdue, send dunning e-mails by level (manual or automatic), and protect the particulier (withdrawal delay, 30 % cap).

**Architecture:** New sub-namespaces of `app/Modules/Finance`: `Payments/` (tables `payments`, `payment_allocations`, computed `Balances`) and `Reminders/` (reminders are `invoice_sendings` rows with `purpose = reminder`, sent by the existing `SendInvoice`). Payment state is never stored on the frozen invoice. Particulier rules live in `InvoiceValidator` and `BillingPlans`, reading `convention_signed_on` exposed by `Sessions\Public\Billing::dossier`.

**Tech Stack:** Laravel 12 / PHP 8.4, PostgreSQL 17 (RLS), Inertia React 19 TS, Pest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-19-0.9.1-reglements-relances-design.md` (and `2026-11-17-0.9-factures-design.md` for invoices).

## Global Constraints

- Every table: `tenant_id uuid not null`, `Rls::enable`, model with `BelongsToTenant`, `HasUuids`, `Auditable`, morph alias registered in `FinanceServiceProvider`.
- Amounts in integer cents, `brick/math` for any arithmetic beyond sums; never float. Days of Paris (`CarbonImmutable::now('Europe/Paris')->toDateString()`).
- French UI; errors through `UserFacingHttpException` (409/422) or validation errors.
- Lists are reference lists: `payment_method` items stored by id, `ReferenceUsage::register(ReferenceList::PaymentMethod, 'payments', 'method_id')`.
- Finance names only its own tables; Sessions/Crm through `Sessions\Public\Billing`, `Crm\Public\Fiches`, `Crm\Public\FicheLinks`.
- Withdrawal delay constant `Particulier::WITHDRAWAL_DAYS = 14`; first instalment cap `Particulier::MAX_ADVANCE_PERCENT = 30`.
- Reminder levels default `[7, 30, 60]`, 1 to 3 strictly increasing integers 1..365; `auto_reminders` default false; scheduled `tms:finance:remind` daily 08:30 Paris.
- Migrations dated `2027_01_17_*`, run with `--database=pgsql_owner`.
- Tests: `docker compose exec app php artisan test --filter=…` from `tms/`; never two suites at once.

## Review Focus

1. A payment allocated twice concurrently to the same invoice beyond its remaining due — the second must be refused (row lock on the invoice, remaining re-read under lock).
2. A credit note correcting a partly paid invoice leaves remaining < 0 — shown as « Trop-perçu », never remindable, never allocatable.
3. A reminder whose e-mail failed — the same level is offered again, not the next one; auto mode retries next day only.
4. A paused invoice or a paid one between page load and « Envoyer les relances » — skipped server-side with a count in the flash, nothing sent.
5. Particulier dossier with no `convention_signed_on` — validation allowed, warning shown; with a date, validation refused until signed + 14 days (Paris day).
