# 0.5.3 — Envoi des e-mails par Microsoft 365 : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** un organisme dont la messagerie est Microsoft 365 (CAP FORMATION : `capformation.net`, SPF strict, SMTP « Basic » retiré par Microsoft) envoie tous les e-mails du TMS (invitations, devis, plaquettes, alertes, modèles) par l'API Microsoft Graph, sans mot de passe de boîte.

**Architecture:** nouveau connecteur `microsoft365_mail` (« Microsoft 365 (envoi des e-mails) ») dans `app/Modules/Connectors/Mail365/` : application Azure de l'organisme en **permissions d'application** (`Mail.Send`, consentement administrateur, `client_credentials`), boîte d'expédition fixe. Un **transport Symfony Mailer** `GraphTransport` envoie chaque message ; `TenantMailer::for()` le choisit quand le connecteur est actif. Aucun code métier ne change : tout passe déjà par `TenantMailer`.

**Spec:** demande de l'utilisateur du 2026-11-16 (« fais le connecteur Microsoft 365 ») ; règle 5 du `CLAUDE.md` (tout logiciel externe passe par un adaptateur dans `Connectors`).

Branche `m365-mail` depuis `main` (v0.5.2). VERSION → `0.5.3`.

## Global Constraints

- Règles du `CLAUDE.md` : secrets des connecteurs chiffrés (`secretKeys`), aucun secret dans le dépôt ni dans les journaux ; messages en français ; TDD ; jamais le texte d'erreur de Microsoft, un jeton ou un secret affiché ou journalisé.
- Annuaire **obligatoire** et précis : GUID ou domaine (`capformation.net`, `xxx.onmicrosoft.com`) — `common` / `organizations` / `consumers` refusés (jeton d'application impossible).
- Jeton d'application mis en cache (clé préfixée par le tenant TMS **et** l'id de la configuration), renouvelé avant expiration, jamais en base.
- Envoi : message ≤ 3 Mo encodé → `POST /users/{expéditeur}/sendMail` en MIME (base64, `Content-Type: text/plain`) ; au-delà → brouillon (`POST /users/{exp}/messages` en JSON) + pièces jointes par **sessions d'envoi** (`createUploadSession`, morceaux ≤ 4 Mo) + `POST …/send`. Les e-mails du TMS vont jusqu'à 20 Mo (plaquettes).
- Erreurs : 401/403 → échec définitif avec message français fixe (« Microsoft 365 a refusé l'envoi : vérifiez la permission Mail.Send et l'adresse d'expédition. ») ; 429/5xx/réseau → exception « réessayable » (les jobs existants réessaient) ; aucun texte de Microsoft.
- Priorité dans `TenantMailer::for($company)` : SMTP propre à la société > **Microsoft 365 (organisme)** > SMTP de l'organisme > messagerie par défaut de l'instance. `deliversNowhere()` en tient compte.
- L'expéditeur affiché est toujours la boîte configurée (Graph l'impose) ; le nom d'expéditeur et le `Reply-To` des messages sont conservés.

## Review Focus

1. **Plaquette de 15 Mo jointe à un devis** → part par le chemin brouillon + sessions d'envoi, reçue entière → test avec faux client HTTP (tâche 1).
2. **Secret expiré ou permission retirée** → échec définitif, statut « Échec » du devis/de la plaquette, message français, aucun texte Microsoft → tâche 1.
3. **Microsoft limite le débit (429)** → nouvelle tentative du job, pas d'e-mail en double → tâche 1.
4. **Deux organismes sur la même instance** → jetons jamais partagés (clé de cache) → tâche 1.
5. **Bouton « Tester »** → envoie un e-mail de test à l'administrateur et affiche un résultat clair → tâche 2.
