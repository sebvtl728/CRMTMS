# 0.8.2 Sauvegardes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Backups visible and triggerable from the app; one-file encrypted export and import to move to another server with no data loss.

**Architecture:** The host stays in charge: `ops/backup.sh` writes `storage/ops/backup-status.json` (outside `storage/app`); the app writes `storage/ops/backup-request.json`, a systemd path unit on the host runs the backup; `ops/export.sh` / `ops/import.sh` reuse restic (`copy` into a standalone repository) and `ops/restore.sh`.

**Tech Stack:** bash + restic (official image) + systemd, bats; Laravel 12 / Inertia React; Pest.

**Spec:** `docs/superpowers/specs/2026-11-17-0.8.2-sauvegardes-design.md` (binding).

## Global Constraints

- No secret (RESTIC_PASSWORD, export password, APP_KEY, DB passwords) in arguments, logs, the app, the status file or the repo; passwords read from the terminal (`read -rs`, twice for export) or env (`TMS_EXPORT_PASSWORD`, `TMS_IMPORT_PASSWORD`).
- `shellcheck -x ops/*.sh ops/install/*.sh ops/release/*.sh` clean; bats tests in `tms/ops/tests/`.
- The `app` container gets no Docker socket and no restic secret.
- Status file path in the volume: `ops/backup-status.json` (volume root, i.e. `storage_path('ops/backup-status.json')` in the app); request file `ops/backup-request.json`. Both outside `storage/app`.
- Page only when `config('tms.mode') !== 'multi'`, right `settings.manage`. Banner threshold: 36 hours.
- French UI; dates shown in Paris time.
- Export file name: `tms-export-<slug>-<AAAAMMJJ-HHMM>-v<version>.tar`, mode 600.

## Review Focus

1. Backup fails half-way (pg_dump error, restic error): status file says failure with a French message, never success (Task 1 bats).
2. Status file missing / corrupt / older than 36 h: page shows an alert, never ✓ (Task 2 Pest).
3. Import with a wrong password, a truncated file, or an export from a newer version: refused, current data untouched (Task 3 bats).
4. Import of an export from an older version: migrations run, app healthy (Task 3 bats with a fixture or a simulated older version tag).
5. Two clicks on « Sauvegarder maintenant » or a click during a nightly backup: one backup only (Task 1/2).

### Task 1: Status file and on-demand backups on the host

**Files:** `tms/ops/backup.sh`, `tms/ops/lib.sh` (helper `write_backup_status`), `tms/ops/install/install.sh` (create `storage/ops` in the volume with the app user's ownership; install `tms-backup-request.path` + `tms-backup-request.service`), `tms/ops/update.sh` (same units/dir, idempotent), `tms/ops/release/files.txt` if new files ship, tests `tms/ops/tests/backup.bats` (+ `install.bats` if units are asserted there).

**Interfaces:**
- Produces: JSON status `{finished_at, success, snapshot_id, error, version, size_bytes, remote: {configured, success}, snapshots: [{id, time, tags}]}` (≤ 60 snapshots, newest first) at volume path `ops/backup-status.json`, written atomically on every exit (EXIT trap), `error` = the French `die` message (no secret).
- Request: when `ops/backup-request.json` exists, the path unit runs `ops/backup.sh --tag manuel`, which deletes the request at start (so a second click during the run creates a new request picked up after).

- [ ] Bats: success writes success=true with the snapshot id and the snapshot list; forced pg_dump failure writes success=false with the French error and no snapshot; status not under `storage/app` (not inside the snapshot); request file consumed by `backup.sh --tag manuel`; no secret value appears in the status file.
- [ ] Implement; `shellcheck -x`; `bats ops/tests/backup.bats` (Docker) green.
- [ ] Commit `feat(ops): backup status file and on-demand backups`.

### Task 3: Export, import and the move test

**Files:** `tms/ops/export.sh`, `tms/ops/import.sh` (new), `tms/ops/restore.sh` (accept a repository override and password from the caller without breaking current use), `tms/ops/install/install.sh` (`--import <file>` / `TMS_IMPORT_FILE`: skip tenant/admin creation, then `import.sh`), `tms/ops/release/files.txt`, tests `tms/ops/tests/move.bats`.

**Interfaces:**
- `ops/export.sh [--output <dir>]` → last stdout line = export file path; also prints its SHA-256.
- `ops/import.sh <file>` → safety backup tagged `pre-import`, restore with `--with-app-key`, `ops/migrate.sh`, `tms:permissions:sync`, `/health`, summary counts (organismes, utilisateurs, entreprises, personnes, sessions, fichiers).
