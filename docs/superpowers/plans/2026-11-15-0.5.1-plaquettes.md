# 0.5.2 — Plaquettes de formation : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** une bibliothèque de plaquettes PDF dans le catalogue, jointes aux devis et envoyables seules depuis les fiches.

**Architecture:** les plaquettes appartiennent au module **Catalogue** (tables, stockage, écrans) et sont exposées au Crm par un service public `Catalogue\Brochures` (le Crm ne nomme jamais leurs tables — motif ajouté à `ModuleBoundariesArchTest`). Les envois passent par l'infrastructure existante (`TenantMailer`, `TenantAwareJob`, modèles d'e-mails, `TimelineProvider`).

**Tech Stack:** Laravel 12, PostgreSQL 17 (RLS), Inertia React, Pest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-15-0.5.1-plaquettes-design.md`.

Branche : `lot-0.5.1-plaquettes` depuis `main` après publication de la 0.5.1 (correctif de la 0.5.0). VERSION → `0.5.2` à la tâche 4.

## Global Constraints

- Règles du `CLAUDE.md` (RLS, `BelongsToTenant`, `TenantStorage` pour tout chemin, français, TDD, `UserFacingHttpException` pour un message d'erreur affiché, données personnelles hors journaux).
- PDF seulement, ≤ 10 Mo par fichier, type vérifié par le contenu (signature `%PDF-`), nom d'origine conservé pour l'affichage, nom de stockage généré.
- Pièces jointes d'un e-mail : ≤ 20 Mo au total, sinon refus avec « Les pièces jointes dépassent 20 Mo : retirez une plaquette. ».
- Versions : remplacer le fichier crée une version ; une version envoyée n'est jamais effacée (corbeille logique de la plaquette seulement ; anonymisation RGPD inchangée car aucune donnée personnelle dans une plaquette).
- Droits : `catalogue.view` (voir, télécharger), `catalogue.manage` (déposer, modifier), `catalogue.delete` (corbeille) ; envoi depuis une fiche = droit de modifier ses actions (`crm.activities.update`) sur la fiche visible.

## Review Focus

1. **PDF piégé ou renommé** (`.pdf` qui est un exécutable, PDF > 10 Mo, fichier vide) → refus avec message français, rien sur le disque → tâche 1.
2. **Plaquette remplacée entre l'envoi et la relance d'un devis** → la relance rejoint la version d'origine → tâche 2.
3. **Formation présente deux fois dans un devis + plaquette rattachée à la formation et à son DAS** → jointe une seule fois → tâche 2.
4. **Échec SMTP de l'envoi d'une plaquette** → statut « échec » visible dans l'historique, texte du serveur jamais affiché → tâche 3.
5. **Utilisateur limité à ses DAS** : il n'envoie qu'à une fiche qu'il voit ; une plaquette d'un autre DAS reste envoyable (le catalogue est commun) → tâche 3.

- `TrainingUsage` : une formation rattachée à une plaquette reste supprimable (le rattachement disparaît) — la suppression d'une formation détache ses plaquettes.
