# Lot 1a – Socle technique Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Livrer le socle du TMS : application Laravel + React multi-organismes isolée par RLS, sociétés (dont SCOP), utilisateurs avec 2FA et rôles, journal d'audit, référentiels paramétrables, couche connecteurs, sauvegardes, et installation / mise à jour Proxmox en une ligne.

**Architecture:** Monolithe Laravel 12 modulaire (`app/Modules/<Module>`), interface React/TypeScript via Inertia (starter kit officiel Laravel React). PostgreSQL 17 avec `tenant_id` sur chaque table métier, double protection : scope global Eloquent + Row-Level Security PostgreSQL (`app.tenant_id` positionné par requête/job ; l'application se connecte avec un rôle non propriétaire). Déploiement Docker Compose (app php-fpm, worker Horizon, scheduler, postgres, redis, gotenberg, caddy) installé dans un LXC Debian 12 par script.

**Tech Stack:** PHP 8.4, Laravel 12, Inertia 2, React 19, TypeScript, Tailwind 4, shadcn/ui, PostgreSQL 17, Redis 7, Horizon, Fortify (2FA), spatie/laravel-permission (teams), Pest 3, Playwright, Bash + bats + shellcheck, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-11-tms-design.md` (§4 lot 1a, §5, §6, §7, §10, §11, §12)

## Global Constraints

- Interface et messages utilisateur en **français** ; `APP_LOCALE=fr`, `APP_FAKER_LOCALE=fr_FR`, fuseau `Europe/Paris`.
- Identifiants : UUID v7 (`HasUuids`) sur toutes les tables métier.
- Toute table métier : `tenant_id uuid not null` + index + politique RLS + trait `BelongsToTenant`. Aucune exception hors liste blanche (`tenants`, `tenant_domains`, `migrations`, `jobs`, `failed_jobs`, `cache*`, `sessions`, `password_reset_tokens`, `permissions`, tables pivot spatie sans données métier).
- Mots de passe : Argon2id, longueur minimale **12**, contrôle `uncompromised()`.
- 2FA TOTP **obligatoire** pour les rôles `admin_organisme` et `direction` ; imposable à tous par réglage d'organisme `security.force_2fa`.
- Aucun secret ni mot de passe par défaut dans le dépôt ou une installation ; `.env` généré par l'installateur.
- LXC : Debian 12, **non privilégié**, `features: nesting=1,keyctl=1`.
- Libellés listes CAP FORMATION (seed) copiés de `Cdc/cdc-activité-commercial.md`.
- Formes juridiques : SARL, SAS, SASU, SA, EURL, EI, SCOP, SCIC, Association, Collectivité territoriale, Établissement public, Autre.
- Cible sécurité OWASP ASVS niveau 2 ; en-têtes CSP stricte, HSTS, `X-Content-Type-Options`, `Referrer-Policy: strict-origin-when-cross-origin`.
- Commits fréquents, messages en anglais conventionnels (`feat:`, `fix:`, `chore:`, `test:`).

## Review Focus

1. **Code exécuté hors requête HTTP** (job en file, tâche planifiée, commande artisan) sans contexte d'organisme → doit lire zéro ligne métier ou lever `MissingTenantContext`, jamais lire toutes les lignes. Test : Task 2 `jobs carry tenant context` + `query without context returns nothing`.
2. **Même e-mail dans deux organismes** → autorisé ; la connexion résout l'utilisateur de l'organisme du domaine courant uniquement. Test : Task 4 `same email in two tenants logs into the right one`.
3. **Installateur relancé sur une installation existante** → ne régénère pas les secrets, n'écrase pas `.env`, ne recrée pas l'administrateur ; s'arrête avec message clair. Test : Task 11 bats `install refuses to overwrite existing env`.
4. **Mise à jour qui échoue en cours de migration** → base restaurée depuis la sauvegarde prise juste avant, ancienne version redémarrée, code de sortie non nul. Test : Task 12 bats `update rolls back on failed migration`.
5. **Suppression d'une valeur de référentiel système ou déjà utilisée** → refusée (désactivation seule possible), l'historique garde le libellé. Test : Task 7 `system item cannot be deleted` + `used item can only be deactivated`.

### Task 2: Multi-organismes et isolation RLS

**Files:**
- Create: `app/Modules/Core/Tenancy/*`, `database/migrations/support/Rls.php`, migrations `create_tenants_table`, `create_tenant_domains_table`
- Test: `tests/Feature/Core/TenancyIsolationTest.php`, `tests/Arch/TenancyArchTest.php`

**Interfaces:**
- Produces:
  - `Tenant` (uuid `id`, `name`, `slug` unique, `status` enum `active|suspended`, `settings` jsonb cast `array`).
  - `TenantDomain` (`tenant_id`, `host` unique).
  - `TenantContext` (singleton) : `set(Tenant $t): void`, `current(): ?Tenant`, `id(): string` (lève `MissingTenantContext` si absent), `clear(): void`, `run(Tenant $t, callable $fn): mixed`. `set()` exécute `select set_config('app.tenant_id', ?, false)` sur la connexion `pgsql` ; `clear()` remet `''`.
  - Trait `BelongsToTenant` : ajoute `TenantScope`, remplit `tenant_id` à la création depuis `TenantContext::id()`, relation `tenant()`.
  - `Rls::enable(string $table): void` (utilisé dans chaque migration de table métier) : `ALTER TABLE … ENABLE ROW LEVEL SECURITY; ALTER TABLE … FORCE ROW LEVEL SECURITY; CREATE POLICY tenant_isolation ON … USING (tenant_id = nullif(current_setting('app.tenant_id', true), '')::uuid) WITH CHECK (même expression)`.
  - Middleware `ResolveTenant` : mode `config('tms.mode')` = `single` → tenant `config('tms.default_tenant')` ; `multi` → recherche `TenantDomain` par `request()->getHost()` ; 404 si inconnu, 503 page « Organisme suspendu » si `suspended`. Réinitialise le contexte en `terminate()`.
  - Trait `TenantAwareJob` : propriété `public string $tenantId` capturée au constructeur ; middleware de job `SetTenantForJob` qui appelle `TenantContext::run`.
