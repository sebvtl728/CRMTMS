# 0.7.1 — Import mieux guidé, abandon d'un import, confier une action : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** proposer une correspondance de colonnes bien plus souvent (et dire pourquoi), offrir un modèle Excel par type d'import, permettre d'abandonner un import non exécuté, et confier une action à un autre utilisateur qui en est prévenu par e-mail.

**Architecture:** module **Crm** uniquement. Import (`app/Modules/Crm/Import/`) : `FieldMap::guess` délègue à un nouveau `ColumnGuesser` (mémoire de l'organisme → en-tête exact → en-tête approchant → contenu) qui rend aussi une raison par colonne ; `ImportTemplate` génère le modèle `.xlsx` avec `openspout` ; `ImportAbandon` supprime un lot non exécuté. Actions (`app/Modules/Crm/Activities/`) : champ « Attribuer à » à la création, endpoint « Confier à… », `CrmVisibility::activities` ouvre toujours l'action à son responsable, e-mail `activity_assigned` (`TenantAwareJob`).

**Tech Stack:** Laravel 12 / PHP 8.4, Pest, Inertia + React 19 / TS, openspout 4 (déjà présent), PostgreSQL 17 RLS.

**Spec:** `docs/superpowers/specs/2026-11-16-0.7.1-import-correspondance-design.md`.

Branche `lot-0.7.1-import-confier` depuis `main` après la fusion de la 0.7.0. VERSION → `0.7.1`.

## Global Constraints

- Règles du `CLAUDE.md` : RLS + `BelongsToTenant` + `Rls::enable` sur toute nouvelle table, français, TDD, `UserFacingHttpException` pour un message affiché, aucune donnée personnelle dans les journaux ni l'audit, clés de cache préfixées par le tenant, `TenantAwareJob` pour les jobs, `TenantStorage` pour les fichiers.
- Une correspondance déjà enregistrée sur le lot (`field_map`) ou venant d'un profil d'import garde la priorité absolue sur toute proposition.
- Proposition par le contenu : 50 premières lignes non vides de la colonne, au moins 80 % des cellules non vides reconnues ; aucune valeur de cellule stockée ailleurs que là où l'import la stocke déjà.
- Colonne ambiguë (deux champs à égalité au même niveau) : laissée sur « Ignorer ».
- Modèle Excel : en-têtes = libellés exacts de `ImportTarget::fields()` ; ligne d'exemple fictive marquée « Exemple — à supprimer » ; feuille « Listes » = valeurs actives des référentiels de l'organisme ; aucune donnée réelle.
- Abandon : seulement aux états `uploaded`, `simulating`, `simulated` ; suppression définitive (lot, lignes, fichier) ; l'import disparaît de la liste ; 409 français sinon.
- Confier : droit `crm.activities.update` et son périmètre sur l'action ; e-mail au nouveau responsable seulement s'il change et n'est pas l'auteur du changement ; jamais le compte rendu ni la suite à donner dans l'e-mail ; message facultatif ≤ 500 caractères.

## Review Focus

1. **En-tête court ou générique** (« Nom », « Tel », « Adresse » sur une cible Rattachements où plusieurs champs se ressemblent) → pas de proposition hasardeuse : ambiguïté = « Ignorer » → tâche 1.
2. **Colonne mixte** (moitié e-mails, moitié vide ou texte) → aucune proposition par le contenu sous 80 % des cellules non vides → tâche 1.
3. **Modèle réimporté tel quel** (ligne d'exemple non supprimée) → la ligne d'exemple est ignorée, aucune fiche fictive → tâche 2.
4. **Abandon pendant une simulation** → le job de simulation s'arrête sans erreur ni ligne orpheline ; abandon d'un import d'un autre utilisateur sans droit « tous les imports » → 404 → tâche 3.
5. **Action confiée à quelqu'un dont le périmètre ne couvre pas la fiche** → il voit et réalise l'action, mais la fiche liée ne s'ouvre pas pour lui (404) et n'est pas cliquable ; aucun e-mail quand on se confie l'action à soi-même → tâche 4.

- Consumes: `Text::key()`, `ImportTarget::fields()`, `ImportTarget::synonyms()`.

- [ ] Failing tests (`ColumnGuesserTest`) :
